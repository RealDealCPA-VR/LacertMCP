Let Claude read and update Lacerte returns, safely.

Lacerte MCP runs on the PC that has Lacerte installed and gives AI assistants like Claude Desktop, Claude Code and Codex a set of well-defined tools: list clients, read any return table, check e-file status, create clients, and write the fields you've enabled, with every change checked and confirmed. Your data never leaves your network. It reads returns; it doesn't prepare them yet (see the table in Part I).

Part I

What it is and how the pieces connect

Intuit's Lacerte SDK only works on the computer where Lacerte is installed. So the MCP server lives on that one "Lacerte PC" and every assistant in the office reaches it over your private Tailscale network. Nothing is hosted in the cloud.

Workstations never touch Lacerte files directly. Every request goes through the server on the Lacerte PC, which knows which device is asking and what it may do.

Reads

Everything in the return tables

Client list and search, DATA1–DATA7 tables, dependents and partners, state rows, detail rows (W-2s, 1099s), forms, e-file status, firm-wide dashboards and year-over-year comparisons.

Writes

Enabled fields and new clients

Client creation, plus single and bulk writes to fields enabled in the field map. Only a few fields are enabled out of the box. Every field write is read back from Lacerte and only reported as done when the stored value matches.

Out of scope

What it doesn't do

It doesn't prepare returns yet, and it never e-files, prints, makes PDFs, or opens organizers or archived files. Lacerte's editor shows a change after you close and reopen that client.

Part II

How a request flows

Here is what happens, in order, when you ask Claude something like "Update Brown's phone number to 555-0142." Each step can stop the request with a clear, coded reason. Nothing is half-done silently.

  1. 1

    Claude picks a tool

    Claude finds the client (lacerte_client_find) and calls lacerte_field_write on the Lacerte PC's /mcp endpoint with the table, client number, field and new value.

    Stops here if
    9017 InvalidArgument
  2. 2

    The server identifies the device

    It asks Tailscale which device made the call, then looks up that device on the control page's Access tab: No access, Read only or Read & write.

    Stops here if

    the device has no access, or only Read access and this is a write

    9001 FieldIsReadOnly
  3. 3

    It uses this connection's context

    Each connection keeps its own tax year, module and data folder (set with lacerte_set_context), so two people's assistants can't redirect each other's writes.

    Stops here if
    9009 ContextNotSet9016 ContextMismatch
  4. 4

    The value and field are checked

    The field must be listed as writable in the field-access map for that module and year. Unknown fields are refused, not guessed. Length, characters and number formats are validated too.

    Stops here if
    9012 UnknownFieldAccess9015 FieldWriteInvalid
  5. 5

    Replays are caught

    If Claude retries with the same idempotency key and the same arguments, the earlier success is returned instead of writing twice. A dry run stops here and shows what would change.

    Stops here if

    the same key arrives with different arguments

    9102 IdempotencyConflict
  6. 6

    Lacerte makes the change

    The write goes through Intuit's SDK, using the newer UpdateTaxReturn path for 2021 and later. Detail rows go through the ODBC driver.

    Stops here if

    Lacerte refuses or isn't reachable

    2 DBFNotAccessable203 NotSignedIn9201 BridgeUnavailable
  7. 7

    The change is read back

    A fresh database connection reads the field again, from the same year and folder the write went to. Only a matching stored value counts as verified. A mismatch also clears the retry record, so trying again really rewrites the field. If the field can't be read back at all, the reply says accepted, not verified instead of guessing.

    Stops here if
    9022 WriteNotVerified
  8. 8

    Claude gets a clear answer

    Every reply has the same shape: success, the result and a correlation id (cid). Social Security, EIN, bank and other secret values are masked. The call also appears on the control page's Activity tab.

    Result
    success: true · verified
Part III

Ways to run it

There are two choices to make: where the assistants connect from, and whether the server talks to real Lacerte data or to built-in sample clients.

Every workstation shares one server

The server runs on the Lacerte PC around the clock, listens on its Tailscale address and on localhost, and serves the control page. Each workstation runs one setup command; you then grant it access on the control page.

  • Installed by install-http.ps1 into %LOCALAPPDATA%\LacertMCP
  • Firewall opened to the tailnet only (100.64.0.0/10)
  • Per-device access, activity timeline and health checks

Control page tabs

  • Overview: live or simulation, the 24-hour Intuit sign-in countdown, ODBC driver, SDK, writable-field map, data folders, Tailscale
  • Access: per device, No access, Read only or Read & write
  • Agents: connected assistants and the client file each is in, plus the copyable setup line
  • Data folders: test reads of each {YY}Tax\{Module}Data folder
  • Activity and Storage

Claude Desktop starts the server itself

For a single person working on the Lacerte PC. Claude Desktop launches LacertMCP.Server.exe over stdio and stops it when it quits. There is no control page or device access list; the person at the PC is the only user.

claude_desktop_config.json 
{
  "mcpServers": {
    "lacerte": {
      "command": "C:/LacertMCP/server/LacertMCP.Server.exe",
      "env": {
        "LACERTE_LIVE": "1",
        "LACERTE_DEFAULT_TAX_YEAR": "2024"
      }
    }
  }
}

Part IV

Setting it up

Set up the Lacerte PC once, then add each workstation. Commands are for PowerShell. Replace <PC> with the Lacerte PC's Tailscale address (the control page shows it).

On the Lacerte PC · once

  1. Install the prerequisites

    Lacerte (first-run setup complete), the 64-bit Lacerte SDK from Intuit's developer portal, and Tailscale signed in to your tailnet.

  2. Run the installer as Administrator

    Download the latest LacertMCP-v*.zip from the GitHub Releases page, unzip it, and run this from that folder. Add -DataRoot \\server\Lacerte if your data is on a share. The installer remembers your options, so re-running it later keeps them.

    powershell -ExecutionPolicy Bypass -File .\install-http.ps1

  3. Sign in to Lacerte

    Open http://localhost:8767/ and choose Sign in to Lacerte, or run the one-time registration. Intuit's sign-in lasts 24 hours; use Reconnect or lacerte-mcp login to renew it.

    & "$env:LOCALAPPDATA\LacertMCP\cli\lacerte-mcp.exe" register

  4. Enable the fields agents may write

    Out of the box only 3 client fields are writable (1040 and 1065 only), and every other field is refused. Enable each field you want agents to change, one at a time, after confirming in Lacerte that it's an input field. Change --module (I, C, S, P, F…), --table and --field to suit. An automatic builder for the whole map isn't available yet.

    & "$env:LOCALAPPDATA\LacertMCP\cli\lacerte-mcp.exe" field-access set --module I --table 1 --field C1_15 --access ReadWrite

  5. Turn on nightly updates

    Optional, and no admin needed. Installs each new release at 03:00; if the PC was asleep or off then, it runs as soon as you're signed in again. Every run is written to update.log.

    & "$env:LOCALAPPDATA\LacertMCP\cli\lacerte-mcp.exe" update --schedule daily
On each workstation

  1. Join the tailnet

    Install Tailscale and sign in to the same tailnet as the Lacerte PC.

  2. Run the one-line setup

    Registers Lacerte MCP with Claude Desktop (classic and Store installs), Claude Code and Codex. No admin rights and no Node.js needed. Re-run it any time to refresh.

    irm http://<PC>:8767/setup.ps1 | iex

  3. Grant access

    On the Lacerte PC's control page, open Access. The workstation shows as Ran setup; choose Read only or Read & write.

  4. Restart Claude and say hello

    Restart Claude Desktop, then ask: "What's my Lacerte session status?" Claude calls lacerte_session_status and lists next steps.

  5. Claude Code only, if you prefer manual setup

    claude mcp add --transport http lacerte http://<PC>:8767/mcp

  6. To remove it from a workstation

    $env:LACERTE_MCP_UNINSTALL='1'; irm http://<PC>:8767/setup.ps1 | iex

Part VI

Access and safety

Tax data is sensitive, so the server is built to say no by default and to prove what it did.

What a device can doNo accessRead onlyRead & write
Connect and see the session status
Read clients, tables, detail rows, e-file status
Dry-run a write to preview it
Write fields and detail rows, create clients
Network

Tailnet only

The server listens on the Lacerte PC's Tailscale address and localhost only, and the firewall admits Tailscale addresses only. Each caller is identified by tailscale whois, never by a header. Requests relayed through a proxy on the PC are refused, and tagged devices are never treated as the owner.

Fail closed

Unknown fields are refused

A field is writable only if the field-access map says so for that module and year. A fresh install allows just 3 built-in fields; you enable others one at a time.

Proof

Writes are read back

Every field write is re-read over a fresh connection. A mismatch returns 9022 instead of a false success.

Preview

Dry runs and read-only contexts

dryRun: true shows what would change without writing. A context set with readOnly: true blocks every write with 9001.

No doubles

Idempotency keys

A retried write with the same key returns the first result. Bulk writes use a key per row, so a half-finished batch can be safely resent.

Privacy

Secrets masked

SSN, EIN, TIN, bank and routing numbers, dates of birth, emails and phone numbers are masked in replies. The activity timeline records which client and field changed, never the value.

Takes effect now

Access changes are immediate

Lowering a device to Read only applies to its open connections straight away, even partway through a bulk write. Setting it to No access disconnects it.

Limits

No device can crowd out others

Each device can hold up to 8 connections (32 in all), request bodies are size-capped, and repeated refused requests are summarized instead of flooding the activity log.

Part VIII

When something goes wrong

Every failure returns success: false with a numbered statusCode, a plain-English userMessage and a remediation telling you what to do. The number's range tells you where to look.

origin: sdk0 – 204

Reported by Lacerte or Intuit's SDK. Fix it in Lacerte: sign in again, close a locked client, correct the tax data.

origin: synthetic9001 – 9299

Raised by this server before touching Lacerte. Fix the request or the setup. 9001–9099 are request checks, 9100–9199 are sign-in and replay issues, 9200–9299 are the SDK connection and server.

9007 LoginExpired or 203 NotSignedIn

Intuit's sign-in lasts 24 hours. Click Reconnect on the control page, or run lacerte-mcp login on the Lacerte PC, then retry.

9012 UnknownFieldAccess on every write

The field isn't enabled for writing. Confirm in Lacerte that it's an input field, enable it with lacerte-mcp field-access set (Part IV, step 4), then ask Claude to call lacerte_reload_schema or sign out and back in. The Overview tab's Writable fields check warns while only the built-in fields are enabled.

Claude says it has to set its context again

The connection was closed, for example after an hour idle, a server restart or an update, so its tax year and folder were forgotten. Ask Claude to set the context again. Writes can never land in the wrong file because of this; they're refused until the context is set.

9022 WriteNotVerified

Lacerte accepted the write, but reading it back returned a different value. A common cause is the return being open in Lacerte. Close it and retry; the retry really rewrites the field, even with the same idempotency key.

9001 FieldIsReadOnly

The context was set read-only, the field or table is read-only (for example DATA6 and DATA7), or this device has Read only access on the control page.

9009 ContextNotSet

Tell Claude which year, module and data folder to work in, for example: "Use 2024 Individual."

A workstation can't see any Lacerte tools

Check that Tailscale is connected on both machines, that the device isn't set to No access on the Access tab, and that Claude Desktop was restarted after setup. Opening http://<PC>:8767/access-check from the workstation shows what the server thinks of it.

My change doesn't show in Lacerte

Lacerte's editor only rereads a client when it is closed and reopened. The write is on disk; reopen the client, or ask Claude to read the field back.

The control page doesn't load

On the Lacerte PC, run "%LOCALAPPDATA%\LacertMCP\server\LacertMCP.Server.exe" --http in a console to see the error. After an update, update.log in the same folder records what happened.

Check the whole install

lacerte-mcp doctor runs 13 checks (Windows, 64-bit, .NET 4.8, ODBC driver, SDK, COM registration, mode, data folders, field map, AppID). Exit 0 means all green, 2 means warnings, 1 means something failed.

Part IX

Keeping it up to date

A new version reaches the Lacerte PC when a version tag (for example v0.2.3) is pushed to GitHub. Code changes on their own don't go anywhere until they are released.

GitHub

Tag pushed

git push origin v0.2.3 starts the Release workflow.

GitHub

Release built

Builds the zip of server, CLI and dumper; GitHub publishes its SHA-256 checksum.

Lacerte PC · 03:00

Check and download

lacerte-mcp update finds the newer release and verifies the download.

Lacerte PC

Back up and swap

Copies the current version to backups\, stops the server and swaps files. Field rules built on this PC are kept; corrected built-in rules arrive.

Lacerte PC

Restart and confirm

Restarts the server and waits for its health check. If the swap fails, the new build reports the wrong version, or the health check fails, the old version is put back and restarted.

Update now

lacerte-mcp update

Only check

lacerte-mcp update --check

Exit code 2 means an update is waiting.

Go back a version

lacerte-mcp update --tag 0.2.1
